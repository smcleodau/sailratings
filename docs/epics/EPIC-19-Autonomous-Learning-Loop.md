# EPIC-19: Autonomous Learning Loop (Agentic Memory & RAG)

## Problem Statement
Currently, our autonomous factory operates with amnesia. If an OpenHands agent struggles with a specific UI dependency, a complex database schema, or a circular import, it has no way to remember the solution for the next task. If a task fails and is placed in the Dead Letter Queue (DLQ), the next agent attempting a similar task is doomed to repeat the exact same mistakes. To reach true autonomy, the factory must implement a Continuous Learning Loop.

## Vision
Every action, tool execution, bash output, E2E test result, and code diff generated by the agents must be embedded and indexed. Before an agent starts coding—and at every step during its execution—it must seamlessly query this "Corporate Memory Index" to learn from past mistakes, reference previous architectural decisions, and avoid known pitfalls.

## Technical Approach

### 1. The Vector Store (Corporate Memory)
Since we already use PostgreSQL for the SailRatings application, we will enable the `pgvector` extension to serve as the unified Agentic Memory Index.
- Create an `agent_transcripts` table with `pgvector` columns.
- Store metadata: Task ID, Epic, Success/Failure Status, Exit Codes, and Diff context.

### 2. Ingestion (The Write Path)
We will extend `api/src/irc_data/temporal/orchestrator/observability.py` and `workflows.py` to capture the entire lifecycle:
- When a `TaskExecutionWorkflow` completes (or fails into the DLQ), a new Temporal Activity `index_agent_run` is triggered.
- It will parse the OpenHands `EventStream` (the raw JSONL transcript of every thought, tool call, and bash output).
- It will extract the "Lesson" (e.g., if a bash command exited with 128, the agent's corrective action is the lesson).
- These lessons and summaries will be embedded using our LLM embedding model and saved to `pgvector`.

### 3. Retrieval (The Read Path)
We will empower the OpenHands Agents to access this memory:
- **Implicit Context:** The Temporal orchestrator will run a semantic search against the task description *before* spawning the agent. The top 3 most relevant past lessons will be injected directly into the agent's initial `system_prompt`.
- **Explicit Tooling:** We will add a custom OpenHands tool called `query_corporate_memory(query: str)`. If an agent encounters a strange bug (e.g., "beartype circular import"), it can query the memory bank to see how it was solved previously.

## Acceptance Criteria
- [ ] PostgreSQL `pgvector` extension is enabled and the `agent_transcripts` table is migrated.
- [ ] Temporal workflow includes an `index_agent_run` activity that saves successful diffs and failed traces.
- [ ] OpenHands agents are injected with a custom `query_corporate_memory` tool.
- [ ] The orchestrator automatically injects relevant historical context into the agent's initialization prompt based on the Notion issue title.
